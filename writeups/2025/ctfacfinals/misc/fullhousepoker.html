🚩 Goal: Reach a 30-win streak.

🔍 Initial Exploration

With the server code in hand, the first step was understanding where randomness came from and how hands were compared. The presence of a global RNG and clearly separated deal and compare functions made this feel like a predict-the-RNG challenge rather than complicated poker strategy.

🕵️ First Observations:

  • A global RNG object (likely time-seeded at connection).
  • Server exposes functions akin to deal_hands(rng) and compare_hands(a,b).
  • Win condition tracked as a streak integer in server output.

The plan: reuse the server's own logic locally with the same RNG to decide whether to bet or fold each round.

🛠️ Investigation Process

📖 Step 1: Read the server code

Inspection showed the RNG is tied to connection time and used consistently for both player and dealer deals. This means that, if we import the server module after connecting, we can reference its GLOBAL_RNG and deterministically simulate outcomes.

Key idea: If we call the same deal_hands(GLOBAL_RNG) and compare_hands the server uses, we can know the result before sending our action.

🧪 Step 2: Build a suggestion engine

I wrote a small helper class that predicts the winner for the next round and chooses b (bet) only when we win; otherwise f (fold). This guarantees no streak resets.

from pwn import remote
from chall import compare_hands, deal_hands, GLOBAL_RNG

class Cheeter:
    def __init__(self, _deal_hands, _compare_hands, rng):
        self._deal_hands = _deal_hands
        self._compare_hands = _compare_hands
        self.rng = rng

    def suggest(self):
        player, dealer = self._deal_hands(self.rng)
        return b"b" if self._compare_hands(player, dealer) > 0 else b"f"

🌐 Step 3: Orchestrate the interaction

The solver connects, loops rounds by sending the predicted action, and watches the printed streak, betting when it's safe. Once near the target, it sends the final bet to claim the win.

host = "d707329b.ctf.ac.upt.ro"; port = 9605
io = remote(host, port)

c = Cheeter(deal_hands, compare_hands, GLOBAL_RNG)
win = False
res = c.suggest() + b"\n"
while not win:
    io.sendafter(b"Action? [b]et / [f]old > ", res)
    io.recvuntil(b"streak: ")
    res = c.suggest() + b"\n"
    win = int(streak := io.recvline().strip()) >= 29 and res == b"b\n"
    print(f"Current streak: {streak}")

io.sendlineafter(b"> ", b"b\n")
io.interactive()

🎯 Step 4: Win and capture the flag

With deterministic predictions, the streak hits 30 without resets. The service then prints the flag.

🧠 Technical Insights

  • Time-seeded RNG pitfalls: Seeding at connection time is predictable if the same RNG instance is reused for all draws.
  • Code reuse advantage: Importing and calling the exact deal_hands/compare_hands avoids re-implementing poker logic and eliminates off-by-one RNG pulls.
  • I/O synchronization: Use blocking reads like sendafter/recvuntil to align predictions with the server's next RNG calls.
Gotcha: Any extra read/write (like a stray recvline) can desynchronize your RNG state from the server and break predictions.

🎯 Key Takeaways

  • Predictable RNG makes "skill" irrelevant—match the server's state and you can't lose.
  • Reusing server functions ensures identical game rules and ordering.
  • Keep network I/O minimal and deterministic to avoid RNG drift.
